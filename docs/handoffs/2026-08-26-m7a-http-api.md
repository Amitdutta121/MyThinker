# Session Handoff

## Completed

- Milestone slice `M7a` completed: FastAPI backend exposing `run_turn`
  (non-streaming) and project state reads, with contract tests -- first slice
  of the redefined `M7: Immersive UI layer`
- `src/mythinking/api.py` (new): `create_app(runtime: ThinkingRuntime | None
  = None) -> FastAPI` factory. `runtime` defaults to `None` and is
  lazily constructed via `create_runtime()` on first use inside the
  `get_runtime` dependency -- building the app (and hitting `/health` or
  `/projects`) does not require an `OPENROUTER_API_KEY`, only `/turns` does
  (through the underlying specialists). Module-level `app = create_app()` is
  the entrypoint `uvicorn` serves. Routes:
  - `GET /health` -> `{"status": "ok"}`
  - `POST /turns` (`TurnRequest{message, project_id}`) -> `AssistantTurn`;
    maps `runtime.run_turn`'s `KeyError` (unknown `project_id`) to 404 and
    `ValueError` (blank message) to 400 -- blank message is actually caught
    earlier by Pydantic's `min_length=1` as a 422 in practice
  - `GET /projects?limit=20` -> `list[ProjectSummary]` (new response-only
    model: `project_id`, `updated_at`, `current_mode`, `title`), newest
    first, backed by `StateRepository.list_recent`
  - `GET /projects/{project_id}` -> full `ProjectState` (404 if unknown)
  - No business logic lives here; every route is a direct call onto an
    existing `ThinkingRuntime`/`StateRepository` method
- `src/mythinking/cli.py`: new `mythinking serve [--host] [--port]` command
  (`run_serve`), lazily `import uvicorn` inside the function so other CLI
  commands don't pay for the import; runs `uvicorn.run("mythinking.api:app",
  host=host, port=port)`
- `pyproject.toml`: added `fastapi>=0.115`, `uvicorn>=0.30` to

  `src/mythinking/api.py` (FastAPI's `Depends(...)` in argument defaults is

- `README.md`: documented `mythinking serve` and the four routes; fixed the

- Tests added: `tests/test_api.py` (new -- `FakeRuntime`/`FakeRepository`
  duck-typed stand-ins over `fastapi.testclient.TestClient`, covering all

## Decisions locked

- Active branch for the session: `m2-drift-control-foundation`
- `M7`'s plan in `docs/IMPLEMENTATION_PLAN.md` was rewritten this session
  (separate commit `91bb1dc`, before M7a implementation started) from a
  minimal-Streamlit UI to an immersive React/Next.js frontend over a FastAPI
  backend, sliced into M7a/M7b/M7c. This handoff is for M7a only.
- The API layer takes a constructor-injected `ThinkingRuntime` for testing,
  exactly like every other component in this codebase (`ThinkingRuntime`
  itself, `FrameAnalyst`, etc.) -- no framework-specific DI container, no
  `Protocol` type; tests just duck-type a `FakeRuntime`, matching the
  existing `tests/test_cli.py` `FakeRuntime` pattern.
- `ProjectSummary` is a response-only Pydantic model defined in `api.py`
  itself, not in `state.py` -- it is an API view, not domain state, and
  mirrors the same four fields `cli.run_list` already prints.
- Full `ProjectState` is returned as-is from `GET /projects/{project_id}`
  rather than a slimmed-down view -- M7c's panels (branches, evidence,
  decisions, next-actions) need the whole object, and there is exactly one
  consumer today (the future frontend), so no projection layer was added
  ahead of a second consumer that would justify one.
- `mythinking serve` binds `127.0.0.1` by default (not `0.0.0.0`), matching
  the "personal, local-first" product framing elsewhere in the repo (e.g.
  local SQLite, no auth).

## Open issues

- No streaming yet (that's `M7b`): `POST /turns` blocks for the full
  `graph.invoke` call, same latency profile as `mythinking chat` today.
- No auth/CORS configuration on the API. Fine for a same-machine
  `mythinking serve` + CLI today; once M7c's frontend is a separate origin
  (e.g. `next dev` on `:3000` talking to `:8000`), CORS middleware will be
  needed -- deliberately deferred to M7c rather than guessed at now.
- `openrouter_app_url` in `config.py` still defaults to
  `http://localhost:8501` (the old Streamlit port) as the OpenRouter
  `HTTP-Referer` header value. It's cosmetic (only affects OpenRouter's
  request attribution, not app behavior) and out of scope for M7a, but M7c
  should update it once the frontend has a real dev port.
- The `StarletteDeprecationWarning: Using httpx with starlette.testclient is
  deprecated; install httpx2 instead` warning appears in the test run. It
  comes from the installed `starlette`/`fastapi` versions, not from this
  repo's code, and does not fail anything. Not investigated further this
  session.
- `M6c` (optional user profile extraction) is still not started -- it was
  skipped in favor of M7 per explicit user redirection this session.
